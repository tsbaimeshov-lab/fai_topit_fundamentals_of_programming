## 2. Псевдокод алгоритмов

### Алгоритм 1. Однопроходный расчет статистик и подсчет элементов выше среднего (`task_2.py`)

```text
АЛГОРИТМ AnalyzeMeasurements(A):
    Вход: непустой список чисел A длины n
    Выход: total, min_val, max_val, even_count, above_avg_count

    total <- 0
    min_val <- A[0]
    max_val <- A[0]
    even_count <- 0

    // Проход 1: сумма, минимум, максимум, четные
    ДЛЯ КАЖДОГО x ИЗ A:
        total <- total + x
        ЕСЛИ x < min_val ТО:
            min_val <- x
        ЕСЛИ x > max_val ТО:
            max_val <- x
        ЕСЛИ x mod 2 == 0 ТО:
            even_count <- even_count + 1

    average <- total / n
    above_avg_count <- 0

    // Проход 2: подсчет значений строго выше среднего
    ДЛЯ КАЖДОГО x ИЗ A:
        ЕСЛИ x > average ТО:
            above_avg_count <- above_avg_count + 1

    ВЕРНУТЬ (total, min_val, max_val, even_count, above_avg_count)
```

### Алгоритм 2. Проверка простоты числа до $\lfloor\sqrt{n}\rfloor$ (`task_2.py`)

```text
АЛГОРИТМ IsPrime(n):
    Вход: целое число n
    Выход: ИСТИНА, если n простое, иначе ЛОЖЬ

    ЕСЛИ n < 2 ТО:
        ВЕРНУТЬ ЛОЖЬ
    ЕСЛИ n == 2 ТО:
        ВЕРНУТЬ ИСТИНА
    ЕСЛИ n mod 2 == 0 ТО:
        ВЕРНУТЬ ЛОЖЬ

    divisor <- 3
    ПОКА divisor * divisor <= n:
        ЕСЛИ n mod divisor == 0 ТО:
            ВЕРНУТЬ ЛОЖЬ
        divisor <- divisor + 2

    ВЕРНУТЬ ИСТИНА
```

### Алгоритм 3. Бинарный поиск с подсчетом сравнений (`task_2.py`)

```text
АЛГОРИТМ BinarySearch(A, target):
    Вход: отсортированный список A длины n, искомое значение target
    Выход: индекс первого найденного совпадения (или -1) и число сравнений

    left <- 0
    right <- n - 1
    comparisons <- 0

    ПОКА left <= right:
        mid <- (left + right) div 2
        comparisons <- comparisons + 1
        ЕСЛИ A[mid] == target ТО:
            ВЕРНУТЬ (mid, comparisons)
        ИНАЧЕ ЕСЛИ A[mid] < target ТО:
            left <- mid + 1
        ИНАЧЕ:
            right <- mid - 1

    ВЕРНУТЬ (-1, comparisons)
```

## 3. Оценки временной и пространственной сложности

### Алгоритмы Задания 2

| Алгоритм | Временная сложность | Дополнительная память | Параметр зависимости |
|---|---|---|---|
| Однопроходная статистика (сумма, min, max, четные) | $O(n)$ | $O(1)$ | $n$ — длина списка |
| Подсчет значений выше среднего | $O(n)$ | $O(1)$ | $n$ — длина списка |
| Линейный поиск | $O(n)$ | $O(1)$ | $n$ — длина списка |
| Проверка простоты числа | $O(\sqrt{N})$ | $O(1)$ | $N$ — величина проверяемого числа |
| Сортировка выбором (Selection Sort) | $O(n^2)$ | $O(1)$ (или $O(n)$ при копировании) | $n$ — длина списка |
| Бинарный поиск | $O(\log n)$ | $O(1)$ | $n$ — длина отсортированного списка |

**Обоснование ограничения делителей квадратным корнем:**
Если составное число $N$ раскладывается на множители $N = a \cdot b$ (где $a, b \ge 2$), то оба множителя не могут одновременно быть строго больше $\sqrt{N}$ — иначе их произведение превысило бы $N$. Следовательно, хотя бы один нетривиальный делитель всегда не превосходит $\lfloor\sqrt{N}\rfloor$. Если до $\lfloor\sqrt{N}\rfloor$ делителей не найдено, их не существует вовсе, и число $N$ простое.

**Сравнение числа сравнений линейного и бинарного поиска (худший случай — элемент в конце или отсутствует):**

| Размер списка ($n$) | Линейный поиск (сравнений) | Бинарный поиск (сравнений) | Во сколько раз бинарный эффективнее |
|---:|---:|---:|---:|
| 10 | 10 | 4 | в 2.5 раза |
| 100 | 100 | 7 | в 14.3 раза |
| 1000 | 1000 | 10 | в 100 раз |

### Сложность построения общей статистики (Задание 5)

Пусть $S$ — количество студентов в словаре `students`, а $M = \sum_{i=1}^{S} k_i$ — общее число всех оценок у всех студентов.
- Вычисление `student_summary` для всех студентов: однократный проход по каждой оценке дает $O(M + S)$ по времени и $O(S)$ дополнительной памяти для хранения итоговых словарей.
- Вычисление `group_summary` и `find_top_students`: один проход по готовым сводкам студентов занимает $O(S)$.
- Формирование рейтинга (`sorted` по среднему баллу без изменения исходного словаря): $O(S \log S)$ по времени и $O(S)$ по памяти.
- **Итоговая сложность:** $O(M + S \log S)$ по времени и $O(S)$ дополнительной памяти (исходный словарь не дублируется целиком).

## 4. Обоснование выбора коллекций (`task_3.py`)

- **Множество (`set`) для уникальных студентов и работ:** реализовано на основе хеш-таблицы. Автоматически исключает дубликаты при добавлении и поддерживает встроенные теоретико-множественные операции (например, пересечение `&` для поиска студентов, сдавших обе работы) за линейное время от размера меньшего множества.
- **Кортеж (`tuple`) как ключ словаря:** кортеж неизменяем (immutable). Если все его элементы также неизменяемы и хешируемы (как `(str, str)` в `(student, laboratory)`), у кортежа вычисляется постоянный хеш (`__hash__`), поэтому он корректен в качестве ключа `dict`.
- **Почему список (`list`) нельзя использовать как ключ словаря:** список изменяем (mutable), поэтому в Python для него намеренно не определен метод `__hash__` (`TypeError: unhashable type: 'list'`). Если бы ключ мог меняться после вставки в хеш-таблицу, его хеш изменился бы, и запись стала бы недоступна по исходному бакету.
- **Словарь (`dict`) против списка (`list`) для поиска по составному ключу:** поиск пары `(student, laboratory)` в списке кортежей требует полного перебора за $O(n)$, тогда как словарь обеспечивает прямой доступ по хешу ключа в среднем за $O(1)$, что критично при частых текстовых запросах (`best`, `attempts`) и инкрементальных обновлениях.

**Средняя и худшая сложность операций использованных коллекций:**

| Коллекция | Добавление (среднее) | Поиск по значению / ключу (среднее) | Поиск (худшее) | Применение в `task_3.py` |
|---|---|---|---|---|
| `list` | $O(1)$ (в конец, `append`) | $O(n)$ | $O(n)$ | Исходный журнал попыток; список попыток студента |
| `tuple` | Неизменяем | $O(n)$ | $O(n)$ | Запись попытки и составной ключ `(student, laboratory)` |
| `set` | $O(1)$ | $O(1)$ | $O(n)$ | Множество студентов; множество сданных лабораторных |
| `dict` | $O(1)$ | $O(1)$ | $O(n)$ | Попытки по студенту; лучший балл и число попыток по ключу |

## 5. Области видимости LEGB, изменяемый аргумент по умолчанию и замыкания (`task_4.py`)

### Схема областей видимости LEGB

```text
+------------------------------------------------------------------+
| B (Built-in): встроенные имена Python (len, str, print, ...)     |
|  +------------------------------------------------------------+  |
|  | G (Global): уровень модуля                                 |  |
|  |   course = "Основы программирования"   (только чтение)     |  |
|  |  +------------------------------------------------------+  |  |
|  |  | E (Enclosing): внешняя функция outer()               |  |  |
|  |  |   completed_labs = 0                                 |  |  |
|  |  |  +------------------------------------------------+  |  |  |
|  |  |  | L (Local): вложенная функция register_lab()    |  |  |  |
|  |  |  |   nonlocal completed_labs  -> изменяет имя в E |  |  |  |
|  |  |  |   label = f"{course}: {completed_labs}"        |  |  |  |
|  |  |  +------------------------------------------------+  |  |  |
|  |  +------------------------------------------------------+  |  |
|  +------------------------------------------------------------+  |
+------------------------------------------------------------------+
```

**Порядок поиска имен внутри `register_lab()`:**
1. `label` — найдено сразу в **Local (L)**.
2. `completed_labs` — объявлено через `nonlocal`, поэтому связывается напрямую с переменной в **Enclosing (E)** и изменяет ее без создания локальной копии.
3. `course` — отсутствует в **L** и **E**, найдено в **Global (G)** (используется только для чтения).
4. `len` / `print` — отсутствуют в **L**, **E** и **G**, найдены в **Built-in (B)**.

### Ошибка изменяемого значения по умолчанию

В определении `def add_result(value, results=[]):` объект пустого списка `[]` создается **один раз** в момент выполнения инструкции `def` (создания объекта функции), а не при каждом ее вызове. Ссылка на этот единственный список хранится в атрибуте `add_result.__defaults__`. В результате каждый последующий вызов без второго аргумента мутирует один и тот же список, накапливая данные прошлых вызовов.

**Исправление:** использовать неизменяемый маркер `None` и создавать новый список внутри тела функции:

```python
def add_result(value: int, results: list[int] | None = None) -> list[int]:
    if results is None:
        results = []
    else:
        results = list(results)
    results.append(value)
    return results
```

### Замыкание в `make_threshold_checker(threshold)`

При вызове `make_threshold_checker(threshold)` возвращается внутренняя функция `checker(score)`. Даже после завершения работы внешней фабрики возвращенная функция сохраняет в своем замыкании (`__closure__`) ссылку на ячейку со значением параметра `threshold`. Поэтому два вызова, например `is_passing = make_threshold_checker(60)` и `is_excellent = make_threshold_checker(90)`, создают две полностью независимые функции со своими собственными сохраненными порогами `60` и `90`.

## 7. Вывод о влиянии декомпозиции на читаемость решения

Разделение интеграционного задания на восемь небольших функций с четкими контрактами сделало код линейным и самодокументируемым:

- **Снижение когнитивной нагрузки:** каждая функция решает ровно одну задачу (поиск минимума, классификация балла, сборка сводки группы или форматирование отчета), поэтому ее логика читается целиком без прокрутки и глубокой вложенности циклов.
- **Изоляция изменений:** изменение порогов оценивания требует правки только в `classify`, а изменение внешнего вида отчета — только в `format_report`, без риска сломать расчет статистики.
- **Упрощение проверки краевых случаев:** обработка пустых списков (`None`) и граничных значений проверяется локально на уровне отдельных функций через `assert`, а не через громоздкие сквозные сценарии.
- **Повторное использование:** базовые агрегаторы (`mean`, `minimum`, `maximum`) переиспользуются как для индивидуальной статистики студента, так и при подсчете показателей всей группы.
