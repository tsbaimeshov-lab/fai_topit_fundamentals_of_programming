## Задание 1. Имена, ссылки и изменяемость

### 1.1. Эксперименты и результаты

* **Эксперимент A (Неизменяемые объекты / `int`):**
  * *Исходный код:*
    ```python
    a = 10
    b = a
    a += 1
    ```
  * *Прогноз:* Переменная `a` укажет на объект `10`. При `b = a` `b` указывает на тот же адрес. При `a += 1` создается новый объект `11`, `a` пересвязывается, а `b` остается равным `10`.
  * *Факт:* Прогноз подтвердился. До изменения `id(a) == id(b)`, после `a += 1` адрес `id(a)` изменился, а `id(b)` остался прежним.

* **Эксперимент B (Изменяемые объекты / `list`):**
  * *Исходный код:*
    ```python
    first = [10, 20]
    second = first
    second.append(30)
    second = [10, 20, 30]
    ```
  * *Прогноз:* `second.append(30)` модифицирует общий список по месту (`first` также станет `[10, 20, 30]`). При `second = [10, 20, 30]` создастся новый объект списка с новым `id`.
  * *Факт:* Результат совпал с прогнозом. `first == second` дает `True`, но `first is second` дает `False`.

### 1.2. Схемы связей в памяти

```text
До переназначения (second.append(30)):
first  ────┐
           ├───> [ List object: id=0x7f8a10, val=[10, 20, 30] ]
second ────┘

После переназначения (second = [10, 20, 30]):
first  ────────> [ List object 1: id=0x7f8a10, val=[10, 20, 30] ]
second ────────> [ List object 2: id=0x7f8b90, val=[10, 20, 30] ]
```

### 1.3. Контрольные вопросы
1. **Меняет ли присваивание `second = first` сам объект?**  
   Нет, оно создает новое имя (ссылку), которое указывает на тот же самый объект в памяти.
2. **Почему операция над неизменяемым объектом создает новый объект?**  
   Неизменяемые типы (`int`, `str`, `tuple`) защищены от изменения своего внутреннего состояния. Любая операция модификации создает новый объект и перенаправляет имя.
3. **Как определить, что два имени связываются с одним объектом?**  
   С помощью оператора тождественности `is` (например, `a is b`), который сравнивает адреса объектов в памяти (`id(a) == id(b)`).

## Задание 2. Поверхностное и глубокое копирование

### 2.1. Сводная таблица операций

| Операция | Создается новый внешний объект | Создаются новые вложенные объекты | Изменения вложенных элементов независимы |
| :--- | :---: | :---: | :---: |
| **Присваивание (`alias = original`)** | Нет | Нет | Нет |
| **Поверхностная копия (`copy.copy()`)** | Да | Нет | Нет (частично) |
| **Глубокая копия (`copy.deepcopy()`)** | Да | Да | Да |

### 2.2. Анализ ошибочной матрицы `[[0]*3]*3`

* **Проблема:** Оператор `* 3` для списков копирует ссылки на исходный вложенный список `[0, 0, 0]`. В итоге все 3 строки матрицы указывают на **один и тот же** объект в памяти. Изменение `matrix[0][0] = 1` меняет нулевой элемент во всех строках одновременно.
* **Правильное решение (генератор списка):**
  ```python
  correct_matrix = [[0] * 3 for _ in range(3)]
  ```

### 2.3. Контрольные вопросы
1. **В чем ключевое отличие поверхностного копирования от глубокого?**  
   Поверхностная копия создает новый контейнер, но копирует ссылки на его внутренние элементы. Глубокая копия рекурсивно дублирует сам контейнер и все вложенные структуры.
2. **Почему `deepcopy` не стоит использовать повсеместно?**  
   Оно требует больше вычислительных ресурсов и памяти из-за рекурсивного обхода и поддержания таблицы `memo` (для обработки циклического копирования).
3. **Когда достаточно поверхностного копирования?**  
   Когда список/контейнер содержит только одноуровневые или неизменяемые данные (`int`, `float`, `str`, `tuple`).

## Задание 3. Подсчет ссылок и время жизни объекта

### 3.1. Анализ работы `sys.getrefcount()`

* Функция `sys.getrefcount(obj)` возвращает количество сильных ссылок на объект. 
* **Нюанс:** Передача объекта в саму функцию `sys.getrefcount()` создает временную внутреннюю ссылку, поэтому результат всегда на **1 больше**, чем фактическое число ссылок в области видимости.

#### Операции и их влияние на счетчик ссылок:
* **Увеличивают счетчик:** Присваивание новой переменной (`b = a`), передача в качестве аргумента функции, добавление в список/словарь/кортеж.
* **Уменьшают счетчик:** Оператор `del`, удаление объекта из контейнера (`list.remove()`, `dict.pop()`), выход переменной из области видимости (`scope`).

### 3.2. Слабые ссылки (`weakref`)

* Использование `weakref.ref(obj)` создает слабую ссылку, которая **не увеличивает** счетчик ссылок объекта (`refcount`).
* Если все сильные ссылки на объект удаляются, объект мгновенно уничтожается, а слабая ссылка начинает возвращать `None`.

## Задание 4. Циклические ссылки и сборщик мусора (`gc`)

### 4.1. Анализ циклической зависимости

Подсчет ссылок (Reference Counting) не может автоматически очистить память при наличии циклических ссылок:
```python
a = []
b = []
a.append(b)
b.append(a)
del a, b
```
После выполнения `del a, b` имена `a` и `b` удалены, но счетчик ссылок каждого списка остаётся равным 1 (так как они ссылаются друг на друга). Объект становится недостижимым из кода, но не удаляется из памяти.

### 4.2. Граф циклических ссылок и работа `gc`

```text
  ┌──────────┐         ┌──────────┐
  │  Узел A  ├────────>│  Узел B  │
  └────▲─────┘         └────┬─────┘
       │                    │
       │   ┌──────────┐     │
       └───┤  Узел C  │<────┘
           └──────────┘
           
  [ Узел D (Независимый) ]
```

* **Результат работы `gc.collect()`:**  
  Сборщик мусора обходит граф объектов, выявляет изолированную группу циклов (узлы A, B, C) и удаляет их. Независимый узел D сохраняется, так как на него есть внешняя сильная ссылка.

## Задание 5. Исследование потребления памяти

### 5.1. Анализ размеров объектов (`sys.getsizeof`)

* Список в Python хранит не сами элементы, а **указатели** на них (по 8 байт на 64-битных системах).
* **Овер-аллокация (Over-allocation):** При динамическом добавлении элементов через `append()` список выделяет память с запасом для обеспечения амортизированной сложности $O(1)$.

### 5.2. Сравнение `list(range(...))` и `range(...)` через `tracemalloc`

* **Материализованный список `list(range(100_000))`:**  
  Создает в памяти массив из 100 000 объектов `int` и сам список указателей. Пиковое потребление памяти составляет **~3800–3900 КБ**.
* **Итератор/Генератор `range(100_000)`:**  
  Хранит только три значения (`start`, `stop`, `step`). Пиковое потребление памяти составляет **менее 1 КБ**.
